The experiment

I wanted to see the complete fine-tuning loop at a scale small enough to understand: record a baseline, train a LoRA adapter, reload it, and test both the desired behavior and an unrelated control.

The base model is HuggingFaceTB/SmolLM2-135M-Instruct. The training set contains variations of one request—asking the model its name—and teaches it to answer, “My name is Simon.” Two arithmetic examples preserve a simple control behavior. This is a demonstration, not a claim that twelve examples are enough for a real product.

The article is also the project. The repository includes the exact training implementation, dataset, one-command experiment, executed notebook, and machine-readable evidence. Readers can inspect or rerun every claim below.

What changed

Before training, the model invented a fantasy identity and gave a verbose arithmetic answer. After training, the exact prompt and a held-out paraphrase both produced the target identity, while the arithmetic control remained correct.

Only 460,800 of roughly 135 million parameters were trainable—about 0.34%. The recorded run completed 60 optimization steps in 59.25 seconds and ended with a training loss of 0.3425. Exact outputs live in before.json, after.json, and training_metrics.json.

Reproduce it

The shortest path is to clone this repository and run the complete experiment. Python 3.12 is the tested version. The first run downloads the base model, so it needs an internet connection and a few hundred megabytes of disk space.

git clone https://github.com/shmcsensei/easy-jev-fine-tune.git
cd easy-jev-fine-tune

python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

python run_experiment.py

The script records the baseline, trains the adapter, evaluates it, writes JSON evidence, and exits with an error if any declared check fails. Generated weights are intentionally excluded from Git because they can be recreated.

Run one piece at a time

# Baseline
python ask.py - "What is your name?"

# Train
python train.py --data data.jsonl --output adapter --epochs 20

# Use the adapter
python ask.py adapter "Introduce yourself in one line."

If you prefer a guided record, open fine_tune_walkthrough.ipynb. It contains the executed outputs and a final assertion that the recorded checks passed.

What the code is doing

1. Format examples as chat

Each line in data.jsonl is one conversation. The tokenizer applies the model’s own chat template. User and padding tokens receive the label -100, so loss is calculated only on the assistant response.

2. Add a small LoRA adapter

Instead of updating the full model, PEFT adds low-rank matrices to the attention model’s q_proj and v_proj modules. The base weights remain frozen. The experiment uses rank 8, alpha 16, dropout 0.05, and a learning rate of 5e-4.

LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    target_modules=["q_proj", "v_proj"],
    task_type="CAUSAL_LM",
)

3. Test more than the training string

The evaluation includes the exact prompt, a paraphrase that was not in the training set, and an unrelated arithmetic control. This is still a very small test, but it is more informative than showing one successful training prompt.

What this proves—and what it does not

If the checks pass, the experiment shows that a small LoRA adapter can steer a compact model’s responses for a narrow family of prompts on consumer hardware. It does not prove that the model learned a durable fact, that unrelated capabilities were preserved, or that the recipe will scale to production.

A serious fine-tuning project needs separate training and evaluation sets, broader regression tests, repeated runs, careful data review, and metrics tied to the real task. Tiny repetitive datasets can overfit quickly. Treat this repository as an inspectable starting point, not a production recipe.

Troubleshooting

If the adapter misses the target, test the exact training prompt first. If that fails, increase epochs gradually. If only the paraphrase fails, add varied examples instead of merely training longer. For out-of-memory errors, reduce the batch size in finetune.py. The scripts choose CUDA, then Apple Metal, then CPU automatically.
